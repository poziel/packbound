# UI icon concept prompt

Fill in only the requested keys and functions from the catalog. For a set, use a
contact sheet to compare optical balance; request separate isolated exports for
production. A rendered contact sheet is not an automatically valid icon atlas.

```text
Create original pixel UI icon concept(s) for Packbound, a dark fantasy inventory
game. Icons: {keys, exact control functions, chosen motifs}. Intended native
source canvas: {24 x 24 menu / 32 x 32 action or reward}; intended display:
{actual slot and scale}. Use the attached reference for compact readable shapes,
not its low contrast or exact designs.

Use a bold stepped silhouette, deliberate connected pixel clusters, consistent
optical weight, open negative space, and approximately two-source-pixel structural
thickness. Center each icon optically with modest clear padding. Keep one clear
motif and at most one secondary cue. The silhouette must communicate the control
at small size without relying on color. Make {potentially confused icon pair}
visibly distinct by shape.

Default rendering: opaque white glyph on a fully transparent background, prepared
for theme tinting. No soft edges, gradients, material texture, glow, random pixels,
decorative runes, cast shadows, baked button/frame, labels, keycaps, counters, or
notification badges. {Explicit small-palette exception only if requested.}

For Attack, Spell, or Block, produce one standalone action glyph per request.
Do not turn a generic Spell glyph into a specific fire-status icon. Preserve
clear tips, handles, gaps, and relevant gesture/guard cues. Keep the whole icon
inside the canvas with no cropped parts.
```

Generated art is a concept even if it looks pixelated. Resolve it onto the exact
native grid, inspect at actual display size, and export/validate the editable
SVG and transparent PNG separately. If the user asks only for concepts, show
that result and label it accurately rather than claiming production readiness.
